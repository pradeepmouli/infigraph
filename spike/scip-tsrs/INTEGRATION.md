## Producer APIs and standard behavior

The CLI follows project references automatically: `scip-tsrs index` at a solution root emits one standard `index.scip`. Empty solution configs and repeated references are supported. `--output` selects an output path, `--project-root` selects the document base, and `--infer-tsconfig` uses an in-memory config for a directory without one. No build or generated source is written into the input project.

In addition to the APIs listed in the original report, project orchestration uses `ParsedCommandLine::project_references`, `resolve_project_reference_path`, `parse_config_file_text_to_json`, and `parse_json_config_file_content`. Inherited members use `get_declared_type_of_symbol_exported` and `get_properties_of_type_exported`. Each program owns compiler/checker regions and is reclaimed with `free_unshared_program` after all checker handles and pointer-keyed caches end. The explicit release and measured solution-root memory support bounded project memory in this workload.

The wire format is the official SCIP 0.10 schema and generated Rust types. It uses typed ranges and explicit UTF-16 columns. Symbol spelling remains `scip-typescript npm ...`, including `key<N>:` and per-document `local N`. There is no private producer protocol or special Infigraph mode. Source signatures, JSDoc, kinds, enclosing symbols/ranges, external-symbol metadata, and implementation/reference flags use the standard fields. JSDoc uses `Node::jsdoc`, `JSDoc::comment`, `JSDoc::tags`, and `get_text_of_jsdoc_comment`; tag boundaries and source spans come from the compiler AST. Descriptions and tags render as Markdown, preserving parameter/return/template/throws/deprecation text, custom tags, Unicode, and fenced or indented examples. Tags-only variable comments are retained. No separate documentation parser or private SCIP field was added.

The relationship design follows [scip-java](https://github.com/scip-code/scip-java/blob/3793579c53edb5c0a51c69315c07faca7376dc3e/scip-javac/src/main/java/org/scip_code/scip_java/javac/ScipVisitor.java); metadata follows [rust-analyzer's SCIP implementation](https://github.com/rust-lang/rust-analyzer/blob/2a362a41a8eb6e090f1a12d9b712df85af6f0c33/crates/rust-analyzer/src/cli/scip.rs). The producer links direct heritage and compiler-resolved inherited members. Full override-signature compatibility and complex mixins remain outside this prerelease.

## Infigraph changes

- The shared language table and installer select `scip-tsrs`. Downloads use the pinned v0.2.1 GitHub release and its three supported archive names.
- Named local values are resolved by document and enclosing scope. The raw SCIP local ID remains in `scip_id`; graph IDs use the usual file/owner/name scheme. Parameters, type parameters, and anonymous structural locals retain the existing exclusion policy.
- Standard documentation and source signatures enrich docstrings. New rows use the document's language and declaration extent; existing AST extents are preserved. Local rows have an enclosing parent and private visibility.
- Value references use `READS` / `WRITES`, honoring SCIP access flags. Explicit type metadata distinguishes class-to-interface and member implementation links from type inheritance. Legacy indexes without rich metadata retain their previous fallback.
- TypeScript and TSX AST extraction distinguishes `implements` from `extends`. The graph's `IMPLEMENTS` table is preserved by normal writes, resolution, incoming-edge restoration, grouping, hierarchy/reference reads, exports, visualization, MCP graph data, pattern detection, checks, review, and cross-repository bridges. AST evidence also preserves `implements SomeClass`, where both SCIP kinds are Class. Shared symbol-edge readers prevent those formats from maintaining separate incomplete lists.
- Rich owner metadata constrains same-name matching. The live probe found that an interface signature could otherwise enrich the only same-named class method, losing `Contract::run`. The fix creates that missing symbol and its implementation edge; reimport repaired the probe's existing graph without rebuilding it.
- The import ledger records an importer revision. Older entries trigger replay even if the input hash and graph generation are unchanged, so consumer improvements can take effect without a source edit.

Scratch producers share one process/timestamp/atomic-counter ID generator. Optimized validation exposed two calls sharing one clock tick; the process counter removes that collision for SCIP, Parquet, and daemon sidecars.

Existing File-node/ignore filtering, source-change snapshots, atomic index output, graph write ownership, growth checks, and edge deduplication remain in the path. External symbols are emitted by scip-tsrs; Infigraph still imports graph nodes only for files its AST index owns. SCIP reference occurrences are not a complete call-syntax model; AST extraction remains part of the call graph.

## Validation

- Native release source: five CLI integration tests passed locally and on all three supported release targets, including checked JavaScript JSDoc and unchanged occurrence tuples. Native formatting and lint passed. The release and latest documentation-only main both have green CI. All six published assets were verified; the Apple silicon executable was run and installed.
- Infigraph workspace coverage: **223 test targets, 3,489 tests passed**, with 35 normally ignored tests. Two Rust documentation tests also passed. Six of the ignored tests were subsequently run as the four required performance gates, and all passed. Two supervisor tests require an intentionally debug-only stall hook; they are now explicitly ignored in release and remain enabled in debug builds. Those two were not exercised locally.
- Final importer reruns: **81 SCIP unit tests, 29 importer integration tests, and one native CLI-to-daemon regression passed**. The native regression covers referenced projects, inherited interface methods, class implementation versus inheritance, scoped private locals, Unicode literal keys, imported JSDoc tags, and repeat imports adding nothing.
- Shared scratch correction: six scratch tests passed. The full suite exposed a separate test synchronization race: it freed a rebuild slot before the client's two-second status poll could announce waiting. The test now observes that notice while holding the slot; the isolated process regression passed in 7.70 s. Production slot-wait behavior did not change.
- Legacy compatibility: all **13 object-literal regressions passed** after limiting caller-span filtering to explicit SCIP kinds. Kind-less property initializers keep their established caller ownership. A same-line rich local reference also remains attributed to its enclosing function.
- Final formatting and all-target, all-feature release lint passed. Current-build timing gates passed: three lock checks, incremental indexing, and group/watch behavior. The graph-growth gate held 2,000 rows across 40 rounds and measured 3,563,520 to 21,307,392 bytes (**5.98x**, below the existing 10x bound).
- The current release candidate passed the public automatic-index command and CLI/MCP readback: **six implementation links, three scoped private locals, three local-read edges**, standard graph schema, and preserved JSDoc descriptions, parameter/return tags, and examples. MCP advertised 101 tools. See the [candidate receipt](.runs/preview-current-readback.json).

Workspace coverage combines the full release run, exact prebuilt executable continuation, and selective reruns of corrected tests. To avoid rebuilding hundreds of large executables during disk pressure, 143 remaining executables were compressed from 8.06 GiB to 1.41 GiB, verified byte-for-byte, restored at their original paths, and run serially with their package working directories and test environment. Completed executables were retired after open-file and identity checks. [Validation receipts](.runs/final-validation.json) retain the checks; the original failed runs and their causes remain in the scratch logs.

The earlier document-store lock failure did not recur with local storage selected explicitly and daemon tests using their isolated harness. The real native CLI-to-daemon regression verifies the routed import. The automatic CLI/MCP readback uses local storage, an owned fixture and registry, and disabled background watching. The normal per-process concurrency/background overrides keep that probe independent of busy host slots. The clean-commit installation check repeats this probe and records its build identities and result in [the installation receipt](.runs/final-installed-readback.json). Previous installed binaries are retained before atomic replacement. The standard commit hook's checks were run manually in release mode to keep the shared debug folder empty.

## Limits

Full override-signature compatibility, complex mixins, inherited documentation expansion, and resolving JSDoc inline link targets remain outside the prerelease. JSDoc tag content and inline source syntax are preserved. Parameter/type-parameter and anonymous-structural local graph rows retain Infigraph's existing exclusion policy; the native SCIP index still carries its normal occurrences. External symbols are emitted but become graph nodes only for files the importer owns. Remote backends are compile/lint checked; their external-service runtime behavior is not verified here.

Debug builds stopped at the user's request and `.shared-target/debug` was cleared. Two guarded cleanups restored 24.96 GiB and 17.44 GiB, leaving 55.15 GiB at that readback. Verification used the existing release cache, one Cargo job and one test thread. The 15 GiB cleanup line triggered retirement of completed test/build outputs while our Cargo was idle. The full suite used a 15 GiB stop guard; the final prebuilt growth check used a 12 GiB reserve after cleanup. Concurrent builds later reduced capacity further, so the final two-program rebuild and installation use a 6 GiB reserve. These reserves do not change test assertions.

Completed standalone dependency outputs (731.96 MiB) were archived to 182.67 MiB and verified against every original file's SHA-256 before retirement. Compiler inputs/fingerprints remain available; the archive preserves dependency metadata. The linked release libraries and installed programs were retained. Source checkouts and other active workers were preserved; sccache cleanup was deferred while their compilers were active. Final capacity is a live host observation, since concurrent builds can consume more than these cleanups release.

## Confidence and recommendation

Confidence is high in the native producer on the supported platforms and measured scopes, and in the locally tested Infigraph integration. Native tuple compatibility remains unchanged, project-graph memory is bounded, and the public CLI/MCP probe verifies interface links, scoped locals, value reads, and documentation. Retain prerelease status while broadening semantic fixtures and running larger production workloads. Infigraph remains a local branch, with local validation; no push or merge is authorized. Prefer in-process tsrs; IPC to `tsc --api` remains a verified fallback transport rather than the recommended implementation.
